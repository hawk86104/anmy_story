## 家庭档案恢复

以下为旧版 CLI 增量恢复说明。当前 COS 附件存储、后台完整 ZIP 备份和整体还原见 [COS 与完整备份](COS_BACKUP.md)。

下载完整 ZIP 后，先检查 `missing-files.json`，再在私有目录解压。`archive.json` 是带版本的索引，`entries/` 可直接阅读，`media/` 与 `originals/` 保存文件。

恢复工具用于导入本站格式的档案，建议在独立环境和空目标家庭中演练。先建立目标家庭账号；用户按邮箱映射，未匹配成员的记录映射到目标家庭首个孩子（没有孩子时映射到家长）。不会恢复账号密码和 AI 密钥，所有恢复项目与记录均保持家庭可见。

在仓库根目录运行（生产环境先停写入、做好完整备份，保持原 `.env`）：

```bash
# 查看用法；正常读取后台配置，不输出密钥。
npm run restore -- --help

# 查看现有家庭 ID（数据库路径以服务器实际配置为准）。
sqlite3 /www/wwwroot/anmy_story/db/mylife.db 'SELECT DISTINCT family_id FROM users;'

# 只检查，不写入；多个家庭时先核对目标账号，不能猜测 ID。
NODE_ENV=production npm run restore -- \
  --source /private/mylife-extracted \
  --family-id 目标家庭ID

# 核对数量、映射和缺失列表后，明确应用。
NODE_ENV=production npm run restore -- \
  --source /private/mylife-extracted \
  --family-id 目标家庭ID \
  --apply
```

默认缺失文件会阻止实际导入；明确接受缺失时才添加 `--allow-missing`。工具拒绝目录外路径与指向目录外的链接。视频重新进入队列，媒体消费者启动后处理；保留原件仍放入私有原件目录。

导入会创建新的素材和项目，并形成新的记录 ID；相同档案的记录按专用标识避免再次创建，但素材和项目不会去重，因此不要反复向同一家庭导入。运行中途失败时保留报告，在隔离环境核对已写入部分后处理，不盲目重试。原账户与数据库完整回滚应使用服务器一致备份，而非家庭 ZIP。
