# 架构与数据边界

## 应用分工

`apps/web` 负责所有访客及孩子使用的界面，默认端口 3000。`apps/cms` 默认端口 3001，提供 Payload 的家长后台、REST API、认证与服务端规则。两者单独构建、单独运行；前台通过同源 `/api` 代理后端，避免在浏览器保存访问令牌。

`packages/shared` 只包含类型、记录方式、日期显示等公开协议，不能包含数据库配置、私钥或 Payload Local API。

当前不需要富文本依赖；手机编辑器使用纯文本字段。依赖锁定 Payload 3.92.0、Sharp 0.35.5，并为迁移工具的 esbuild 与后台的 DOMPurify 固定安全补丁版本，升级时需要保留审计与实际迁移验证。

本阶段使用 SQLite 与受保护的本地媒体目录，适合先服务一家人。生产需要持久磁盘；对象存储和数据库服务的替换保持在后台，不改变手机页面。

## 访问规则

- `users`：孩子可读取及修改自己，不可修改角色、家庭或公开预授权；家长管理同家庭成员。只有家长能进入 Payload 管理界面。
- `entries`：家庭成员可读同家庭记录；孩子修改自己创建的记录，家长协助修改同家庭记录。禁止通过普通 API 永久删除，改用归档。
- `media`：默认只有本家庭能够读取，文件地址也执行服务端访问检查。只有被批准快照引用的媒体允许访客读取；撤回后立即失去公开权限。
- `entries` 原始 REST 数据始终不向访客开放。匿名 `/api/public/entries` 返回单独构建的 `publicSnapshot`，不返回家长说明、原文、家庭 ID、账号或私人版本。

`familyId`、`author`、`originalText`、版本编号和公开快照均由后台确定，忽略客户端伪造值。素材跨家庭关联会被拒绝。所有记录与附件响应使用 `no-store`，避免撤回后仍从应用/CDN 缓存获得旧公开内容。已下载到访客设备的副本无法远程撤销。

## 保存与公开

`status`（draft/saved/archived）和 `visibility`（family/public）分开保存。孩子提交直接成为 `saved`，无需家长审批。

未获预授权的孩子选择公开时，记录仍为家庭可见，`publicRequested=true`、`reviewStatus=pending`。家长批准后生成限定字段的公开快照。修改已公开记录时，原来的批准快照继续展示，新文字先留在家庭空间；主动改回家庭可见则清除快照和公开媒体关系。

阶段 A 提供最新稿审批与公开快照基础。固定的申请版本、审批事件表、原子并发比较将在专用审核工作台中完成。当前版本号检查可以发现已经保存的旧版本，不宣称已经解决同一时刻两个写请求的全部竞争条件。

## 草稿和版本

编辑过程每 600ms 将内容及待传附件写入 IndexedDB，键包含家庭、用户和记录 ID；设备草稿不会自动出现在其他设备。主动“存草稿”写入后台，后续可在时间轴筛选草稿。上传中退出会触发浏览器离开提示。

每条记录使用随机 `clientId` 唯一标识，提交响应丢失后按它找回已有记录，再保存当前修改，避免生成重复记录或丢弃新内容。

首次 `originalText` 不接受覆盖。Payload 保存最多 100 个编辑版本，每版包含实际修改人的账号与当时称呼，记录发生时间与系统首次保存时间独立。完整永久版本归档与版本恢复入口安排在阶段 C，不能把当前的 100 个滚动版本当作长期备份。

## 媒体

普通图片：前台 Canvas 优化，后台 Sharp 再验证、自动旋转、移除 EXIF，最长边 2048px / WebP 82。证书或文字图使用 4096px / WebP 92。照片按优化版本存储，本阶段未提供长期保留原图开关。

视频：上传原件后 `queued → processing → ready/failed`。记录可以关联排队视频直接保存。独立进程使用 FFprobe 验证输入，FFmpeg 生成最长 1280×720 范围内且不放大的 H.264/AAC MP4，并移除 metadata；验证输出、更新数据库后才删除临时原件。转码失败保留受保护原件，页面可重试。进程锁确保单机单队列消费者，重启时恢复中断任务。

音频：浏览器 MediaRecorder 录制，或上传已有文件；本阶段保留原音频，未接语音识别服务。单文件大小从服务端 `MAX_UPLOAD_MB` 下发，默认 100MB，最多 12 份附件。
