# COS 附件与完整备份

本次本地调试、临时库清空/还原演练、宝塔升级及 EO 发布的逐步操作见 [本地测试与宝塔升级步骤](UPDATE_20261028_COS_BACKUP.md)。

## 存储与部署

服务端使用腾讯云官方 `cos-nodejs-sdk-v5`，通过 HTTPS、Host 签名、Content-MD5、上传后的 HEAD 校验写入对象。规则参见[腾讯云 Node.js SDK 快速入门](https://cloud.tencent.com/document/product/436/8629)。密钥只写入 `apps/cms/.env` 或部署环境，不进入 Git、浏览器代码、备份 ZIP。

复制 `deploy/tencent/cms.env.example` 中的 `MEDIA_STORAGE=cos`、COS 和备份配置到服务器真实 `.env`，填写两项凭据。桶为 `anmy-story-1253949117`，区域 `ap-nanjing`，CDN 为 `https://anmy-story.icegl.cn`。COS API 以 Bucket/Region 定位存储桶；账号信息不用于拼接桶名。

新附件的对象键为 `media/YYYY-MM-DD/随机文件名`，原件为 `media/YYYY-MM-DD/originals/随机文件名`。日期使用上海时区的记录创建时间，补记的发生日期不会改变目录；编辑旧记录上传附件时沿用该记录创建日期。素材库、头像、项目封面单独上传时使用上传日期。还原保留归档日期。

云端对象使用 private ACL，授权后返回一小时有效的 CDN 签名 URL，COS 签名包含源站 Host。CDN 须透传完整查询参数、Range 并以 COS 默认域名回源，遵循源站 no-store；不配置长期公共缓存。游客只能从公开记录/头像/封面接口取得对应链接。原件下载仍检查同家庭家长权限。视频转码只使用短暂工作文件，完成后上传替换、清理旧对象与临时目录；录音转写、下载和备份直接读 COS。

上传普通附件上限仍由 `MAX_UPLOAD_MB` 控制；完整 ZIP 上传默认 1024 MB，解压总量默认 4096 MB，单个附件最大 500 MB、索引最大 64 MB、最多 50000 个 ZIP 条目。超出上传上限时可在服务器使用解压后的命令行增量恢复；如调整限制，同步调整反向代理、前台代理和服务器内存容量。

升级时先停止 CMS 与媒体消费者，备份一致性数据库和服务端配置，安装依赖，然后在生产模式执行 `npm run db:migrate --workspace @mylife/cms`。开发库使用 `npm run dev:prepare`。本次新增媒体位置字段及持久文件清理队列。

```sh
# 检查实际 COS/CDN 上传、读回、Range 和匿名访问限制；临时对象验证后删除。
cd apps/cms
node --import tsx src/scripts/check-storage.ts
cd ../..

# 预览旧附件迁移，不写入和删除。
npm run media:migrate
# 按最早关联记录的创建日期上传；SHA-256 读回一致、数据库位置提交后删除本地副本。
npm run media:migrate -- --apply
```

迁移可重复运行，已迁移记录会跳过；排队/处理中视频暂不迁移。旧文件已缺失时跳过并写入 `data/media-migration-report.json`，以非零状态提示；上传或校验失败会停止并保留本地副本。完成后重新启动 CMS 与媒体消费者。生产服务器上的旧附件需在该服务器执行迁移，本地脚本不会访问宝塔磁盘。

## 使用后台

家长在 `/app/manage/settings` 或 Payload 后台首页下载完整 ZIP，选择 ZIP 后先预检，再输入“还原整体备份”执行。预检令牌绑定家长账号和家庭，30 分钟有效；临时文件在执行完成或到期后清理。ZIP 包含本家庭所有实际附件、原件、记录、可用历史、项目、主页、成员资料和服务设置，也包含私密内容及 AI 服务密钥。下载后请私密保管。登录密码、COS 凭据、PAYLOAD_SECRET 和服务器配置不打包，需要独立备份。

若历史素材文件在备份前已缺失，ZIP 仍保留数据索引，并在 `missing-files.json` 中列明；该包不能通过整体还原预检，需要先补齐缺失内容。请检查报告，不能将存在缺失项的包当作完整可恢复备份。

整体还原替换当前家庭的记录、素材、项目、主页与服务设置，保留备份中的公开状态。已有成员按邮箱匹配，当前操作者保留家长身份；缺少的成员重新建号，密码随机生成，需要家长重设。还原前先下载当前资料。路径穿越、重复文件、缺失附件及 SHA-256 不一致均拒绝。数据库清空与恢复处于同一事务，失败回滚，并清理此次新上传的文件。

清空需输入“清空所有历史记录以及素材”，删除当前家庭全部记录、原生版本、长期历史、项目和附件原件，移除主页图片；保留账号、主页文字、主题和服务设置。其他家庭不受影响。排队或处理中视频会阻止清空/还原。

文件删除意图随数据库事务写入持久队列，提交后删除 COS 对象。网络失败保留任务，媒体消费者会持续重试，后台也可点击“重试清理文件”。当前网页会清除本家庭的设备草稿；其他设备已经保存的离线草稿需在对应设备清理。

命令行 `npm run restore` 保留旧版增量导入行为（默认只检查、明确 `--apply` 后写入、记录保持家庭可见）；与后台整体替换用途不同。JSON 导出只有数据索引和设置，完整还原需要 ZIP 中的实际文件。
